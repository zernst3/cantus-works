What's in an inspection report

An inspection ends with one package: a short PDF anyone can read, a workbook with every problem and files your team can load straight into its tools. Here is what's inside, and who it's for.

The PDF: for you and anyone who needs to trust the code

  • A plain-language summary · where the code stands, and answers to the questions you asked when you requested the quote.
  • The first three fixes · the changes that matter most this week, each with its hours.
  • The most serious problems · what's wrong, where, what to do and how long it takes, worst first.
  • Every other fix · grouped by area and put in order: first, next and later.
  • What your code already does well · your own conventions, and the rules your code passed.
  • Dependencies · the packages with known security advisories, and the version that fixes each one.
  • How it was done and its limits · what was read, what wasn't and why, and what an inspection can't show.

It's dated, tied to the exact version of your code that was read and signed by me. A non-technical investor can read it in a few minutes.

The workbook: for the engineer who does the work

Every problem is a row: the file and line, the rule it breaks with a link to the standard behind it, the suggested fix, the hours and how certain the finding is. Problems that repeat across your code are grouped as one fix that lists every place. The workbook also shows what was ruled out and why, and every file that wasn't read, so nothing is hidden.

The files: for your tools

  • A ticket file · one ticket per fix, ready to import into Jira or Linear.
  • CSV and JSON · the same data for spreadsheets, dashboards or your own scripts.
  • A README · what each file is and how to import the tickets.

Who uses what

  • A founder reads the summary and the first three fixes, and plans from the hours.
  • An investor or customer reads the summary and checks what was read and who signed it.
  • Your next engineer works from the workbook and the tickets, and gets a map of the codebase on day one.

The report is complete on its own. If you want help with the fixes I can do them, but you never have to.
